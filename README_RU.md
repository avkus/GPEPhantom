# CLI Proxy API Plus

[English](README.md) | Русский

Прокси-сервер, предоставляющий совместимые с OpenAI/Gemini/Claude/Codex API-интерфейсы для CLI. Теперь также поддерживает OpenAI Codex (модели GPT) и Claude Code через OAuth. Вы можете использовать локальный или многоаккаунтный доступ к CLI через клиенты и SDK, совместимые с OpenAI (включая Responses)/Gemini/Claude.

## Поддержка Amp CLI

CLIProxyAPI включает интегрированную поддержку [Amp CLI](https://ampcode.com) и расширений Amp IDE, позволяя использовать ваши подписки Google/ChatGPT/Claude OAuth с инструментами кодирования Amp:

- Псевдонимы маршрутов провайдеров для API-паттернов Amp (`/api/provider/{provider}/v1...`)
- Management-прокси для OAuth-аутентификации и функций аккаунта
- Умный фоллбэк моделей с автоматической маршрутизацией
- **Сопоставление моделей** для маршрутизации недоступных моделей к альтернативам (например, `claude-opus-4.5` → `claude-sonnet-4`)
- Безопасный дизайн с конечными точками управления только для localhost

Когда вам нужна форма запроса/ответа конкретного семейства бэкендов, используйте специфичные для провайдера пути вместо объединённых конечных точек `/v1/...`:

- Используйте `/api/provider/{provider}/v1/messages` для бэкендов в стиле messages.
- Используйте `/api/provider/{provider}/v1beta/models/...` для конечных точек генерации с областью модели.
- Используйте `/api/provider/{provider}/v1/chat/completions` для бэкендов chat-completions.

Эти маршруты помогают выбрать поверхность протокола, но сами по себе не гарантируют уникальный исполнитель вывода, когда одно и то же видимое для клиента имя модели повторно используется в нескольких бэкендах. Маршрутизация вывода по-прежнему разрешается из модели/псевдонима запроса. Для строгой привязки к бэкенду используйте уникальные псевдонимы, префиксы или иным образом избегайте пересекающихся видимых для клиента имён моделей.

**→ [Полное руководство по интеграции Amp CLI](https://help.router-for.me/agent-client/amp-cli.html)**
